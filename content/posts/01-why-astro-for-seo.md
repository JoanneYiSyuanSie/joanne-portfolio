## 前言：行銷人為什麼要管網站怎麼蓋？

做內容行銷久了會發現一件事：文章寫得再好，如果網站本身跑得慢、結構亂，搜尋引擎跟讀者都不太買單。速度跟結構是內容的地基，地基不穩，內容再好也發揮有限。

所以我決定自己把網站蓋起來，不是為了當工程師，而是為了真的弄懂：搜尋引擎是怎麼看一個網站的「體質」的。這篇就講我選了什麼、為什麼這樣選。

## 一、靜態網站是什麼意思？

先講最關鍵的差別。靜態網站的意思是：**網頁在發布之前就已經做好了**。寫好一篇文章，建置的時候就把它變成一份完整的 HTML 檔案，放在伺服器上。有人來訪，伺服器就直接把檔案交出去，不用現場組裝。

相對的，WordPress 這類系統是「動態」的：訪客每次打開一頁，伺服器都要去問資料庫、把內容拼成網頁，再送出來。這個過程需要時間，也需要主機去運算。

差別不在誰比較「高級」，而在做的事不一樣。靜態網站把工作提前到發布時做完，訪客來的時候就沒什麼事要做，所以回應通常比較快，搜尋引擎的爬蟲也不用等它慢慢組裝。

## 二、Core Web Vitals 是在量什麼？

Google 用一組叫 Core Web Vitals 的指標來衡量「使用者實際感受到的網站體驗」。不用記英文縮寫，知道它在量什麼就好：

- **主要內容出現的速度**：打開頁面後，最主要的文字或圖片多久才出現。這是讀者第一個感覺到的事。
- **版面會不會跳動**：頁面載入時，文字或按鈕會不會突然移位。看過那種正要點連結、結果按鈕被圖片擠下去的經驗嗎？那就是版面跳動。
- **點了之後多久有反應**：按按鈕或切換選單時，頁面多久才回應。如果頁面塞了太多 JavaScript，主執行緒被卡住，點擊就會感覺遲鈍。

這些指標不是抽象的分數，而是讀者實際的體感。技術 SEO 在意的就是這些體感。

## 三、WordPress 跟靜態網站的取捨

WordPress 是最多人用的選擇，好處是功能多、不用寫程式。但功能是靠外掛堆出來的：SEO 一個外掛、表單一個外掛、快取一個外掛、社群分享又一個外掛。每多一個外掛，頁面載入時就要多處理一些東西，檔案也會變大。

再加上每次請求都要查資料庫，伺服器回應第一個字節的時間（TTFB）就很難壓得低。對搜尋引擎的爬蟲來說，等動態頁面慢慢組裝也是在耗它的時間。

靜態網站的取捨剛好相反：功能少、要自己接，但換來的是簡單跟快速。沒有資料庫要查，沒有一堆外掛要載，爬蟲一來就能直接讀到完整的文字跟結構。

本站選的是 Astro。它是靜態網站生成器，建置時就把文章編成乾淨的 HTML，而且預設幾乎不送 JavaScript 到瀏覽器，只有真的需要互動的地方才載入（Astro 叫它 Islands）。這讓頁面保持輕量，也讓爬蟲不用等 JavaScript 跑完就能讀到內容。

## 四、本站的架構長什麼樣子？

簡單說，本站的架構是這樣：

- **Astro** 負責把 Markdown 文章編成靜態 HTML。
- **Cloudflare Pages** 負責放這些檔案、發給訪客。
- **Tailwind CSS** 負責樣式。
- 需要互動的區塊（例如文章頁的渲染）用 React 做成小元件，只在需要的地方載入。

沒有資料庫、沒有後端伺服器。文章就是 Markdown 檔案，改了就重新建置、重新發布。成本低，維護也簡單。

## 小結

學 Technical SEO 最有用的地方，不是背一堆指標名稱，而是開始從兩個角度看網站：讀者打開頁面感覺如何，搜尋引擎爬過來能不能順利讀到內容。靜態網站不是唯一答案，但它讓這兩個問題都變得比較單純，這就是我選它的原因。
